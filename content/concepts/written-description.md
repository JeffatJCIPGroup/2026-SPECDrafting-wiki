# Written Description（書面描述）

## 定義

Written description 是 [[statute-35usc112|35 U.S.C. §112]] 第一段的要求：說明書必須包含對發明的書面描述，且描述必須「full, clear, concise, and exact」，使該技術領域的一般技術人員能夠製造與使用該發明。此要求的核心是：申請人必須「possess（擁有）」所請求的發明。

## 詳細說明

### 法律標準

Written description 要求確保：
- 申請人確實「擁有」申請日當時的發明
- 說明書揭露的內容足以支持請求項的範圍
- 若申請人修改請求項，修改後的內容必須有原始揭露的支持

### 與 Enablement 的區別

| 要求 | 核心問題 | 違反後果 |
|------|----------|----------|
| Written Description | 申請人是否「擁有」（possess）該發明？ | 請求項缺乏說明書支持 |
| [[enablement]] | 一般技術人員能否製造與使用？ | 說明書不足以讓他人實施 |

兩者密切相關，但 written description 更側重於「申請人對發明的擁有與控制」，而 enablement 側重於「是否足以讓他人實施」。

### 常見觸發場景

- **修改請求項**：審查過程中加入原始申請書未揭露的技術特徵
- **繼續申請（continuation）**：主張優先權，但新請求項超出原始揭露
- **化學/生技領域**：請求功能性定義的化合物類別，但說明書僅揭露少數具體化合物

## 實務要點

1. 說明書中應涵蓋所有可能的請求項語言，包括最寬的概念和具體的實施例
2. 修改請求項時，確認每個修改後的元素在原始說明書中都有對應揭露
3. 對於化學/生技發明，揭露足夠的具體化合物或結構，以支持功能性定義的請求項
